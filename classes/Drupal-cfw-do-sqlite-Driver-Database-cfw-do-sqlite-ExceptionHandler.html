\Drupal\cfw_do_sqlite\Driver\Database\cfw_do_sqlite ExceptionHandler

Maps host SQL errors onto Drupal's exception vocabulary.

Core's handler classifies by SQLSTATE, reading it off a \PDOException: any 23xxx becomes an IntegrityConstraintViolationException. There is no PDO here and ctx.storage.sql returns a message, not a SQLSTATE, so the same classification has to come from the message text.

This matters beyond tidiness. Drupal treats a unique-key collision as control flow in several places - Merge, key/value writes, user registration - and catches IntegrityConstraintViolationException specifically. A driver that reported those as a generic wrapper would turn a recoverable collision into a fatal error.
